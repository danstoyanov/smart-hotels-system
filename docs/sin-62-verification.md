# SIN-62 verification

## Result

Google ADK is connected behind a small adapter. Each invocation has separate working
state and read-only tools for the reviewed local hotel records. Completed answers
and tool-generated source references save together. The existing chat calls the
real API, restores saved sources after refresh and shows the current assistant mode.
Gemini runtime model: `gemini-3.8-flash`, as requested by the user.

## Checks performed

- `uv sync --locked` installed the baseline; `uv add 'google-adk>=1.18,<3'` resolved
  Google ADK 2.13.0 and google-genai 2.33.0 into `uv.lock`.
- `scripts/check.ps1`: all 55 Python tests passed, including real PostgreSQL
  integration tests and six new deterministic ADK/tool checks. All three SSE tests,
  lint, format, JavaScript syntax and hotel data validation passed.
- The new route test verifies owned history, saved source references, no held model
  transaction, safe provider failure and reset after a failed reply.
- PostgreSQL tests used a newly initialized temporary PostgreSQL cluster, loopback
  port 15472, database `sin62_assistant_test`. It contains disposable test data only.
  A separate `sin62_assistant_demo` database served the local page. Existing task
  databases and the normal application database were not used.
- `frontend/tests/assistant.browser.cjs` passed in headless Chrome at 1440×1200 and
  390×844: saved source links, refresh, unsafe-link rejection, plain-text rendering,
  failure/retry, reset, no horizontal overflow and no page errors.
- Browser screenshots were visually inspected. They use controlled API fixtures,
  not Gemini output: [desktop](screenshots/sin-62-desktop.png) and
  [mobile](screenshots/sin-62-mobile.png).
- `git diff --check` passed.

The first full database run had one failed test because its expected migration list
did not include the new migration. The expectation was updated and the full check
then passed. Offline checks validate code contracts, not model answer quality.

## Reference lookup

At the user's request, checked only `backend/app/agent.py` and `backend/app/tools.py`
at the commit listed in `REFERENCE.md`. Useful patterns: fresh ADK invocation state,
bounded tool/model calls, current hotel evidence, low thinking and source references
generated by application tools. No reference application was imported. Royal Crest
Manor data, Europe/Kyiv, the existing session API and PLAN task scope remain in use.

## Live acceptance remains open

No paid model calls or cloud changes were made in this task run. The user selected
Gemini 3.8 Flash. Google Cloud project, location, access method and approved spending
limit are still needed before a live check. The command in README runs four small
cases and stops on failure without automatic retry. Review known facts, missing
prices and refusal to claim availability or booking success. Check the local
website against the real model as well.

SIN-62 and M1 remain incomplete until that evidence exists and the user accepts and
merges the PR. Stub mode remains the default. Source links identify records read;
they do not prove that every generated claim is supported. No account-wide monetary
budget is implemented in T05.
